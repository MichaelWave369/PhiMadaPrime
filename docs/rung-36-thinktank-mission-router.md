# R36 · Mission Router: Council → PhiBot → Human

## Purpose

The R35 ThinkTank rendered seven responsive views; **R36 adds a deterministic, review-only routing workbench** between the validated Agentora completion plan and the conceptual core operators, Ori Council, and PhiBot roles.

Open **ThinkTank → Mission Router**. You may also enter through the PhiBots or Ori Council screen.

## How it works

1. Accept only proposals already parsed through `missionQueue` from a validated Agentora plan and matching the current public fleet catalog.
2. Pick a proposal from the filterable list (up to 60 shown; filter searches the full supplied proposal collection).
3. Match a **documented deterministic text rule**, not an AI model or live operator. Security, release, verification, documentation, UI, integration and architecture categories have explicit suggested operator / Ori council / bot mappings. Unmatched proposals fall back to manual triage through BrainC, Scout Ori and Scout Bot.
4. Read `plan.freshness` and compare the mission's plan HEAD to a **fresh, identity-matching, explicitly requested** public GitHub observation. A matching HEAD is **ready for human review**, not verified quality or permission to execute.
5. Use **Inspect current GitHub HEAD** to reuse the existing on-demand read-only inspection path. **Visit repository desk**, **Pin**, and **Mark reviewed locally** reuse R35/R3 UI functionality.
6. **Copy review dossier** exports a text proposal combining the deterministic routing explanation, HEAD evidence limits, and the canonical `handoffText` generated by Agentora's validated workflow.

## Authority and evidence

- The operators and council are role blueprints. They do not speak, deliberate, run a model, or direct installed bots in R36.
- Proposed PhiBot routes do not install manifests, invoke an API, queue work, grant credentials, merge changes, deploy, or approve a PR.
- No new GitHub writes or browser credential forwarding. All GitHub observations are user-triggered through existing `fetchRepoSignals`.
- On a moved HEAD, stale observation, missing commit, unmatched repository ID, fallback catalog example, unvalidated plan or stale plan, the router **fails closed** to `RECHECK_REQUIRED` or refuses to route.
- A matching HEAD gives `READY_FOR_HUMAN_REVIEW`, which is explicitly **not** a remote authorization nor evidence that all CI checks passed.
- The existing Mission Board and R34 pinned PhiBot manifest inspector remain available separately.

## Tests

`tests/thinktank-routing.test.mjs` covers deterministic role selection, safety-first priority, valid matching HEAD, stale and changed HEADs, unknown signals, catalog identity checks, untrusted dispatch flags, and the non-executing handoff.

Run `npm test` and `npm run build`; existing PhiMada CI runs both and publishes no automatic merge.
